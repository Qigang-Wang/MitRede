# 整体方案

## 1. 产品定位

本系统不是在线 PowerPoint 编辑器，而是“现有 PDF 演示材料的互动播放层”。它将静态 PDF 页和实时互动页组织为一条统一的演示序列，让主持人不必在 PowerPoint、投票工具和结果页面之间切换。

核心体验可以概括为：

```text
上传 PDF → 插入互动 → 启动房间 → 扫码参与 → 网页播放 → 实时结果 → 会后导出
```

## 2. 方案边界

### 2.1 输入

- 首版只接收 PDF。
- 用户自行将 PowerPoint 转换为 PDF。
- 系统保留原始 PDF，并生成缩略图和播放用页面图。

### 2.2 输出

- 网页端全屏演示。
- 手机端互动页面。
- 实时统计和文本结果。
- CSV 数据导出。
- 后续可生成 PDF/HTML 会后报告。

### 2.3 已知限制

PowerPoint 转成 PDF 后会丢失动画、逐步出现、视频、音频、宏和大部分交互。系统应在上传入口说明这一点，避免用户把本产品理解为完整 PPT 播放器。

## 3. 内容结构

静态页和互动页统一建模为演示节点：

```text
Presentation
└── Nodes（有序）
    ├── PDF_PAGE
    ├── MULTIPLE_CHOICE
    ├── RATING
    ├── WORD_CLOUD
    ├── OPEN_QUESTION
    └── AI_SUMMARY
```

每个节点包含：

- 稳定标识。
- 在演示中的顺序。
- 节点类型。
- 题目或页面内容配置。
- 视觉配置。
- 默认互动规则。
- 创建与更新时间。

现场答案不直接写入演示节点，而是归属于一次独立场次，保证重复使用同一演示时结果互不污染。

## 4. 信息架构

### 4.1 管理首页

- 我的演示。
- 最近编辑和最近播放。
- 新建演示。
- 历史场次与结果。
- 管理入口，仅管理员可见。

### 4.2 演示编辑器

建议采用左侧节点缩略图、中间画布、右侧属性栏结构：

```text
┌────────────┬──────────────────────────┬──────────────────┐
│ 页面序列   │ 当前页面预览             │ 属性与行为       │
│            │                          │                  │
│ PDF 1      │                          │ 题目             │
│ PDF 2      │       当前画布           │ 选项             │
│ + 投票     │                          │ 答题设置         │
│ PDF 3      │                          │ 结果显示设置     │
└────────────┴──────────────────────────┴──────────────────┘
```

页面之间显示插入按钮，点击后选择互动类型。互动节点允许拖动排序；PDF 页面首版建议保持原顺序，避免用户误以为改变了原始 PDF。

### 4.3 主持播放页

投屏区域只显示观众需要看到的内容；鼠标移动或快捷键唤出控制栏。控制栏包含：

- 上一页、下一页。
- 当前页码。
- 开放/锁定答题。
- 显示/隐藏结果。
- 在线人数和已提交人数。
- 房间二维码。
- 结束演示。

敏感的审核操作和 AI 草稿应放在演讲者视图，不应意外显示在投屏区域。

### 4.4 参与端

参与端保持极简，仅显示当前动作：

- 等待主持人开始。
- 当前题目和输入控件。
- 提交成功状态。
- 当前题目已锁定。
- 等待下一题。
- 场次已结束。

参与端不显示 PDF 内容，以减少手机流量和版权扩散风险；若未来有明确需求，再增加“允许查看当前 PDF 页”的演示级开关。

## 5. 状态模型

### 5.1 演示场次状态

```text
DRAFT → LOBBY → LIVE ⇄ PAUSED → ENDED
```

- DRAFT：场次已创建但未开放加入。
- LOBBY：允许加入，等待主持人正式开始。
- LIVE：正常播放和互动。
- PAUSED：暂停公共状态变化，可恢复。
- ENDED：场次结束，不再接受答案。

### 5.2 互动状态

```text
NOT_OPEN → ACCEPTING ⇄ LOCKED
```

结果展示使用独立布尔状态 `results_visible`，不混入上述答题状态。这样可以覆盖以下现场用法：

- 开放答题但隐藏结果，减少从众效应。
- 锁定答题后一次性公布结果。
- 展示实时结果并继续收集答案。
- 暂时收起结果进入讨论。

### 5.3 主持控制原则

- 服务端保存权威状态和单调递增版本号。
- 只有持有控制权的主持端可以改变公共状态。
- 参与端发送答案，不能自行改变当前页。
- 重连客户端先获取完整快照，再继续接收增量事件。

## 6. 互动页面设计

### 6.1 选择题

- 默认先隐藏结果，主持人可切换实时显示。
- 投屏以大字号柱状图为主，同时显示票数和百分比。
- 多选题必须明确“最多选择几项”。
- 如果配置正确答案，应在锁定后由主持人主动揭示。

### 6.2 评分

- 不只展示平均分，同时展示分布，避免掩盖意见分化。
- 投屏端突出样本数，防止少量回答被误读为整体意见。

### 6.3 词云

- 新词先进入审核与归一化流程，再进入公开词云。
- 支持主持人合并同义表达。
- 不适合只靠固定敏感词表，应保留人工隐藏入口。

### 6.4 开放问答

- 主持端审核区与投屏展示区分离。
- 允许按时间、点赞和主持人置顶排序。
- 被隐藏的内容不能进入 AI 总结上下文。

### 6.5 AI 总结

AI 总结是互动结果上的派生节点，不应成为播放链路的强依赖：

1. 主持人选择数据范围和总结模式。
2. 系统异步提交总结任务。
3. 演讲者视图显示草稿。
4. 主持人编辑、重新生成或确认。
5. 确认后，投屏端才展示总结。

推荐模式：

- 主要观点。
- 共识与分歧。
- 高频主题。
- 待解决问题。
- 行动项。
- 下一步追问。

## 7. 现场可靠性设计

### 7.1 页面预加载

- 播放开始前加载当前页、前一页和后两页。
- 翻页后继续滑动预加载窗口。
- 页面图失败时可降级为直接渲染原始 PDF 页。
- PDF 静态页缓存到浏览器，使短时断网仍可继续翻阅已缓存内容。

### 7.2 实时连接恢复

- 浏览器检测断线并指数退避重连。
- 每个事件带房间版本号。
- 重连时先请求最新房间快照。
- 答案提交使用请求标识保证幂等，避免重试导致重复计票。

### 7.3 备用操作

- 主持端明确显示网络连接状态。
- 实时系统异常时，PDF 仍然可以继续播放。
- 提供手动刷新房间状态入口。
- 正式推广前支持备用主持设备接管。

## 8. 数据生命周期

建议将数据分为三类：

1. 演示资产：原始 PDF、页面图、题目配置。
2. 现场状态：当前页、互动开关、在线连接，生命周期短。
3. 互动结果：答案明细、汇总、审核状态和 AI 结果。

建议管理员分别设置保留策略。例如现场连接记录在场次结束后短期清理，匿名答案保留一段时间，演示资产由创建者主动归档或删除。实际期限需结合所内数据管理制度确定。

## 9. 分阶段范围

### 阶段一：可用闭环

- 用户登录。
- PDF 上传与处理。
- 演示节点编辑器。
- 单选、多选和开放问答。
- 房间码与二维码。
- 主持播放和手机参与。
- 实时状态与结果。
- 基础审核。
- CSV 导出。

### 阶段二：正式推广能力

- 评分和词云。
- 演讲者视图。
- 备用主持与控制权转移。
- 敏感词配置。
- 会后报告。
- 统一身份认证。
- 管理后台与数据清理。

### 阶段三：AI 与效率增强

- AI 总结、行动项和追问。
- PDF 文本抽取。
- 根据 PDF 推荐互动位置和题目。
- 互动模板与演示模板。

## 10. 成功判断

该系统首阶段是否成功，主要看以下指标，而不是题型数量：

1. 创建者能否在五分钟左右将已有 PDF 加入两到三个互动节点。
2. 参与者能否在没有培训的情况下扫码并完成第一次提交。
3. 集中提交时是否稳定，结果是否正确。
4. 主持端是否能在断线、刷新或误操作后快速恢复。
5. 使用者是否愿意在下一次所内会议中继续使用。
